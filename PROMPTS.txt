Travel Expense Manager - Original User Prompts
================================================

This file contains the original prompts given by the user to build this travel expense management system.

## Prompt 1 — Project Goal

You are building a personal travel expense management web application.

This system is used by a UK contractor to plan and record work trips and produce monthly expense reports with VAT calculations and a PDF evidence binder.

The application will initially be single-user and run locally, but must be designed so it could later be:

Open sourced
Hosted on AWS
Extended with email parsing
Extended to multi-user

The system must be cleanly architected and domain-driven, not just CRUD screens.

Use the following stack:

Backend:

Python 3.12
FastAPI
SQLAlchemy ORM
Alembic migrations
SQLite initially (must be easy to switch to PostgreSQL later)
Pydantic models
File uploads stored on local filesystem

Frontend:

React
TypeScript
Vite
Material UI (or similar modern component library)
Mobile-friendly responsive design

Other:

Docker + docker-compose
Makefile for common commands
Pytest for backend tests
Generate PDF files for reports

Uploaded files must be stored using this structure:

uploads/YYYY/MM/filename.ext

Filenames must be human-readable and machine-readable and include the date:

Example:

uploads/2026/03/train_2026_03_31_DON_KGX.pdf
uploads/2026/03/hotel_2026_03_31_premier_inn_invoice.pdf
uploads/2026/03/meal_2026_03_31_wagamama.jpg

The database must store:

Original filename

The storage system must be abstracted so it could later be replaced with S3.

Important Business Logic (Must Be Implemented in Service Layer)
Overnight Expense Calculation
nights = end_date - start_date

For each night:
    create ExpenseItem:
        category = "Incidental Overnight Expenses"
        amount = 5.00
        date = overnight date
        trip_id = Trip.id
        is_billable = true

If trip dates change:

Delete existing incidental items
Recreate them
VAT Calculation

If STANDARD:

ex_vat_amount = amount / 1.2
vat_amount = amount - ex_vat_amount

Else:

ex_vat_amount = 0
vat_amount = 0

These should be calculated automatically when ExpenseItem is created or edited.

Monthly Report Logic

For a given month:

Include:

All ExpenseItems in that month
Group by Trip
Include items not linked to Trip

Totals required:

Standard Rated Gross
Standard Rated VAT
Zero Rated
Out Of Scope
Total Expenses
Billable Total
Non-Billable Total
Evidence Binder Ordering Logic

EvidenceItems included in binder must be:

Ordered by:

MIN(ExpenseItem.date) for all ExpenseItems linked to that EvidenceItem

Each EvidenceItem appears once only in the binder.

Constraints & Data Integrity Rules

These are important — include them in the agent prompt:

ExpenseItem must have:
category_id

ExpenseItem must have at least one of:

OR be marked as "monthly expense"

(You may implement a boolean is_monthly_expense)

Deleting Trip should delete Journeys, Legs, and related ExpenseItems (but NOT EvidenceItems)
Deleting ExpenseItem should NOT delete EvidenceItem
Deleting EvidenceItem should remove links but not ExpenseItems

## Implementation Notes

The system was built following these key principles:
- Domain-driven design with clear separation of concerns
- Service layer containing all business logic
- Storage abstraction for future cloud migration
- Mobile-first responsive design
- Modern Python tooling with uv and pyproject.toml
- Comprehensive testing and code quality tools
- Docker containerization for easy deployment
- Clean API design with automatic documentation
